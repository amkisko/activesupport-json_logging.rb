# Resource and budget mode

Run this mode for every audited tree that can execute. Skip only when the tree never becomes executed bytes, and state that reason. Keep the same finding fields as the rest of the skill.

## Time versus utilization

Time behaviour lives in dimension 6 and hot-path mode: latency, throughput, RAIL, Big-O, N+1. Resource utilization is separate: memory, CPU, storage, network, electricity. Capacity is the named ceiling the product documents and measures against.

## Measure first

Benchmark before claiming cheaper, smaller, or greener. Until RSS, heap, CPU time, disk, compressed payload, and energy or a stated proxy (CPU-seconds, joules) are measured, those claims are inference. Name joules when a meter exists. A missing meter is not a skip of the mode. Name the bench, the fixture, and the machine class.

## Default budget

Aim for the lowest numbers that still meet the product requirement. Large consumption is allowed when the requirement names it; document that budget and keep measuring against it. Offsets and kWh-per-GB stories do not substitute for a lower measured energy.

## Shared hardware

Ask whether this tree's memory, CPU, storage, network, or energy use starves, delays, or evicts other software on the same machine, container, phone, or plant. Until co-location is measured, that claim is inference.

## What to name

Quantity metrics: shipped size (JS bundle, native binary, container image, gem, assets), resident memory and heap, CPU time and duty cycle, storage growth, network bytes, energy or a stated proxy (CPU-seconds, joules). Call out mixed compressed versus uncompressed numbers. JS parse cost is not image bytes of the same size. Transferred bytes are not a linear network-energy saving.

Industry starter numbers (page-weight defaults, store download ceilings, carbon-rate formulas) stay related reading. Measure the audience, then set the house budget.

Partition-child disk growth and parallel-worker CPU are instances of this mode.

Related: `minimal-implementation` calibrates on real hardware. WSG 3.1 covers web performance and energy goals. SCI names a rate of energy, grid intensity, and embodied hardware per functional unit; this mode owns measured energy and, when the tree chooses hardware, embodied hardware. Grid intensity is ops and location. A library audit may stop at measured energy; a full SCI score is extra. ISO 25010 resource utilization and compatibility are related reading for other software as a resource, not house MUST.
