# Whole-line byte budget

## Participants

- vesan

## Decisions

- Add JsonLogging.max_line_bytes, off by default (nil). A default budget would silently shorten lines on transports that have no per-line limit.
- Configure it with a module setter only, not a Railtie option, because Puma can format lines before the Rails application loads.
- Apply the budget in LineEncoder.build_line and LineEncoder.to_json_line, which every formatter, logger, fallback, and event subscriber line passes through.
- Shorten the longest string values first and mark the line with "truncated": true. When 24 passes cannot fit the budget, replace the line with severity, timestamp, "truncated": true, and a message naming the budget.
- Require a budget of at least 256 bytes so that replacement line always fits.
- Lines within the budget pay one bytesize comparison and no allocation.

## Effects

- Added lib/json_logging/line_cap.rb and the JsonLogging.max_line_bytes setter.
- Added spec/json_logging_max_line_bytes_spec.rb covering the default, setter validation, formatter, logger, and event subscriber lines, plain strings, multibyte cuts, the replacement line, and lines within budget.
- Documented the setting in README and CHANGELOG Unreleased.
- Hot path budget, 200,000 info calls with a five-field hash on Ruby 4.0.6: 23.0 allocations per line on main, with the budget off, and with a 9,500-byte budget. Time per line stayed within run-to-run noise (5.3 to 6.1 microseconds).
